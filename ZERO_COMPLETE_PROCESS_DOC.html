1. Project Overview

Zero ek hyperlocal marketplace hai jisme hum khud maal store nahi karte. Hum gaav aur city dono ke customers ko unke aas-paas ki dukaanon se connect karte hain aur har order par commission lete hain.

Core idea

• Customer apni pasand ki dukaan se samaan order karta hai

• Vendor apne products khud manage karta hai

• Delivery boy order deliver karta hai (vendor khud add karta hai)

• Admin poora platform control karta hai

Apps in the system

AppPathKaun use karta hai
Backend APIapps/backendSab apps isse connect hoti hain
Customer Websiteapps/webSirf customer (browser)
Mobile Appapps/mobileCustomer + Vendor + Delivery (ek hi app)
Admin / Vendor Webapps/adminAdmin + Vendor (web panel)

2. Business Model & Vision

Revenue

• Har dukaan par commission rate set hota hai (e.g. Ramu Kirana = 10%, Shyam Store = 12%)

• Order complete hone par commission calculate hota hai

• Admin dashboard par total commission, vendor payouts, shop-wise breakdown dikhta hai

Gaav-friendly design principles

• Bade buttons, kam English, zyada icons

• 3 languages: Hindi, English, Marwadi (Marwadi)

• Voice search har jagah (bol kar khojo)

• Order 2–3 tap me

• Simple OTP login (password nahi)

Marketplace rules

• Ek cart me sirf ek shop ke products (single-shop cart)

• Customer 2 tarah se order kar sakta hai:

1. Particular vendor se direct

2. Sab vendors ko request bhej kar — jo accept kare

4. User Roles & Login

4.1 Customer Login (Website + Mobile)

Flow:

1. Customer apna phone number daalta hai

2. Backend OTP generate karta hai (dev mode me console/log me dikhta hai)

3. Customer OTP verify karta hai

4. Naya user ho to automatically customer role milta hai

5. Optional: Shop code daal sakta hai (login/signup ke time ya baad me)

API:

• POST /api/v1/auth/otp/request — OTP bhejo

• POST /api/v1/auth/otp/verify — OTP verify + JWT token

• Body me optional: shop_code (4–12 characters)

4.2 Member Login (Mobile only — Vendor / Delivery / Admin)

Flow:

1. Mobile app me "Member Login" option

2. Sirf pehle se registered staff accounts OTP le sakte hain

3. Role ke hisaab se alag screen khulti hai:

- vendor → Vendor Dashboard

- delivery_boy → Delivery Home

- admin → (mobile me limited; full admin web panel se)

API:

• Same OTP endpoints, lekin context: "member" — sirf existing staff

4.3 Vendor Web Login (Admin panel)

• Vendor admin website (apps/admin) par login karta hai

• Role = vendor → sirf "My Shop" menu dikhta hai (products, orders, banners, notices, delivery boys)

4.4 Session

• JWT token (30 days default)

• Refresh token support

• Har request me Authorization: Bearer <token>

• Language header se UI language set hoti hai

6. Shop Code System

Kya hai?

Har dukaan ka ek unique shop code hota hai — jaise RAMU01, SHYAM01.

Customer yeh code daal kar apni app/website us dukaan se bind kar sakta hai.

Kyon important hai? (Gaav use case)

• Gaav me log aksar ek hi kirana se judte hain

• Shop code daalne se customer ko sirf us dukaan ke products dikhte hain

• Vendor apna code customer ko bol kar/share kar sakta hai

Technical flow

1. Har store ke paas stores.shop_code column (unique, 4–12 chars)

2. Code format: shop name se base + number, e.g. RAMU + 01 = RAMU01

3. Customer shop code daalta hai:

- Login/signup: POST /auth/otp/verify me shop_code

- Ya baad me: PATCH /auth/me me shop_code

4. Backend users.preferred_store_ids me us store ki ID save karta hai

5. Poori catalog ab filter ho jati hai

APIs

• GET /catalog/stores/by-code/:code — code se dukaan dhundho (preview)

• PATCH /auth/me — { shop_code: "RAMU01" } apply karo

• Shop code clear: { shop_code: null } → filter hata do

Mobile screen

• ShopCodeScreen.tsx — code enter, preview, apply, skip

9. Order Process (Direct Order)

Cart rules

• Ek cart = ek hi shop ke items

• Dusri shop ka product add karoge to warning / cart clear

Checkout steps

1. Delivery address choose/add karo (pincode serviceability check)

2. Payment method: COD ya Online (UPI via PayU)

3. Order summary: items + delivery fee + penalty (agar pending) + total

4. Place order

Order statuses (lifecycle)

placed → confirmed → preparing → ready_for_pickup
→ assigned → out_for_delivery → delivered

(cancelled — kisi bhi stage par possible, rules ke saath)

Vendor side

• Naya order aata hai → Accept / Reject

• Accept ke baad: preparing → ready_for_pickup

• Ready par delivery boy assign karo

Customer side

• Orders list me status dikhta hai

• WhatsApp par order confirm bhejne ka option (mobile)

15. Product Chat (Customer ↔ Vendor)

Concept

Har product par customer us product ki dukaan ke vendor se baat kar sakta hai.

Chat product-specific hai — ek customer + ek product = ek chat thread.

Kyon?

• "Yeh item available hai?"

• "Delivery kitne baje tak?"

• "Thoda discount milega?"

• Gaav ke log call ki jagah chat prefer kar sakte hain

Security

• Sirf chat ke participants access kar sakte hain:

- Customer jisne chat kholi

- Us product ke store ka vendor

• Koi teesra user chat nahi dekh sakta

Flow

Product detail → "दुकान से बात करें"
→ POST /chats { product_id }
→ Chat screen khulta hai
→ WebSocket se real-time messages
→ History on-demand load (pagination)

Message types

TypeDescription
textNormal text message (max 2000 chars)
voiceAudio recording (upload + play)

Real-time (WebSocket)

• Socket.io same server par (/socket.io)

• JWT token se authenticate

• Events: chat:join, chat:leave, chat:send, chat:new_message

REST fallback (jab socket na ho)

• POST /chats/:id/messages — text ya voice bhejo

Chat list

• Customer: apni saari product chats

• Vendor: apni dukaan ki saari customer chats (VendorChats screen)

Database

• product_chats — (product_id, store_id, customer_user_id) unique

• product_chat_messages — (chat_id, sender_user_id, body, message_type, audio_url, created_at)

16. Voice Messages in Chat

User experience

1. Chat screen me 🎤 mic button dikhta hai

2. Tap → recording shuru

3. Dubara tap (⏹) → recording stop + upload + send

4. Samne wale ko audio player dikhta hai — sun sakte hain

Technical flow

User records audio
→ POST /uploads/voice (multipart file, max 5MB)
→ Server saves: /uploads/voice-<timestamp>.webm
→ Returns: { path: "/uploads/voice-xxx.webm" }
→ Socket emit: chat:send { chatId, message_type: "voice", audio_url }
→ DB save + broadcast chat:new_message
→ Receiver plays via <audio controls> (web) or player (mobile)

Supported audio formats

• webm, mp4, m4a, wav, ogg, aac (browser/device dependent)

Permissions

• Web: browser microphone permission

• Mobile: RECORD_AUDIO (Android) + NSMicrophoneUsageDescription (iOS)

Platforms

PlatformComponent
WebVoiceRecordButton.tsx + ChatMessageBody.tsx
MobileVoiceChatRecorder.tsx + VoiceMessagePlayer.tsx

28. Security Rules

Authentication

• JWT on all protected routes

• Role-based access: customer, vendor, delivery_boy, admin, super_admin

Chat security

• assertChatAccess() — sirf customer ya us store ka vendor

• Socket join me bhi same check

Shop code

• Invalid code → 404 error

• Code sirf active stores ke liye

OTP

• bcrypt hashed storage

• TTL (default 5 min)

• Max attempts limit

• Dev mode: OTP console me (production me MSG91 SMS)

Voice upload

• Sirf authenticated customer/vendor

• audio_url chat me sirf /uploads/ path accept hota hai (path traversal protection)
